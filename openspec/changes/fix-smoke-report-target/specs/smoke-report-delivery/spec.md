# Spec Delta

## Purpose

规定冒烟报告的发布去向：报告必须落在承载本次真实代码改动的那个 GitLab 项目，
并能从工作区目录机械推导出该项目，避免把报告发到聚合仓库的指针 MR 或用例仓库。

## ADDED Requirements

### Requirement: 报告必须发到承载真实代码改动的项目

冒烟报告的发布目标 SHALL 是承载本次缺陷真实代码改动的 GitLab 项目。聚合仓库的
子模块指针 MR 与用例仓库 MUST NOT 作为发布目标。

#### Scenario: 改动在子仓库

- **WHEN** 缺陷的代码修复发生在子仓库（如 `sie-iidp-ai-agent-web`），且聚合仓库只提交了子模块指针
- **THEN** 报告发布到该子仓库对应的 MR，聚合仓库的指针 MR 不含报告正文

#### Scenario: 缺陷本身只改根仓库

- **WHEN** 缺陷的改动全部位于根仓库的工作区级文件（`openspec/`、`docs/`、`AGENTS.md` 等）
- **THEN** 报告发布到聚合仓库的 MR，并以该 MR 作为 `报告链接`

#### Scenario: 目标指向用例仓库

- **WHEN** 指定的发布目标等于冒烟用例所在仓库
- **THEN** 发布被拒绝，退出码非 0，提示需指向本次修复代码所在的仓库

### Requirement: 目标项目可从工作区目录推导

系统 SHALL 支持通过指定改动所在的子目录，从该目录的 git 远端地址推导出 GitLab 项目路径，
使调用方不必手工填写项目路径。

#### Scenario: 按子目录推导

- **WHEN** 调用方给出子目录 `sie-snest`，该目录的 `origin` 指向 `http://<host>/ipaas/sie-snest.git`
- **THEN** 推导出的项目路径为 `ipaas/sie-snest`，并按该路径发布报告

#### Scenario: 两种指定方式同时出现

- **WHEN** 调用方同时给出了显式项目路径与待推导的子目录
- **THEN** 以子目录推导结果为准，并输出告警说明显式值被忽略

#### Scenario: 子目录不是独立仓库

- **WHEN** 指定的子目录不存在，或其中没有 git 仓库
- **THEN** 发布前即失败并说明原因，不进入用例执行阶段

### Requirement: 发布前校验目标 MR 的实质内容

在向目标 MR 发送报告前，系统 SHALL 读取该 MR 的改动内容并判断其是否只包含子模块指针推进。
只包含指针推进的 MR MUST NOT 接收报告正文。

#### Scenario: 目标 MR 只推进子模块指针

- **WHEN** 目标 MR 的全部改动都是 `Subproject commit` 行
- **THEN** 报告不发送，命令以非 0 退出，并指出该 MR 只推进指针、真正改动位于哪个子仓库

#### Scenario: 目标 MR 含真实代码改动

- **WHEN** 目标 MR 的改动中包含指针行以外的文件变更
- **THEN** 校验通过，报告正常发布到该 MR

#### Scenario: 无法读取 MR 改动

- **WHEN** 读取 MR 改动失败（权限不足、接口不可用、网络异常）
- **THEN** 输出告警说明校验未执行，仍继续发布报告，不因此阻断交付

### Requirement: 报告发布结果可复核

发布成功后，系统 SHALL 输出指向该报告的 MR 评论链接，并把它写入善治备注所需的内容中，
使报告链接可与 MR 链接并列写入缺陷备注。

#### Scenario: 发布成功

- **WHEN** 报告已作为评论发到目标 MR
- **THEN** 终端输出该评论的链接，且善治备注内容中包含同一条链接

#### Scenario: 发布失败

- **WHEN** 发送评论失败（凭证失效、MR 不存在等）
- **THEN** 命令输出失败原因与本地报告路径，且不把该次冒烟当作已交付证据
